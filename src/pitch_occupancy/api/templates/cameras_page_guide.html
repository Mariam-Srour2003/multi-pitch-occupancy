What you need before you start
  • The camera on the same network as the Mini-PC that runs this system (same switch, router or VLAN), or reachable over a VPN.
  • The camera's IP address (from its app, the router's device list, or the NVR).
  • A username and password that is allowed to view live video. A separate "viewer" user is better than the admin account.
  • RTSP turned on in the camera's settings (often under Network > Advanced, or "Integration protocol" / "ONVIF").
Which address to use for your camera

Replace user, pass and IP with your own. If the password contains @, /, ? or #, write them as %40, %2F, %3F, %23.

Recommended camera settings
  • Sub-stream is enough. One picture a minute is all this system takes; 720p or even 640x360 works and is lighter on the network.
  • Use H.264 rather than H.265 (H.265+) if pictures fail to arrive.
  • Give each camera a fixed IP (or a DHCP reservation in the router) so the address does not change after a power cut.
  • Keep the camera's clock synced (NTP) so its on-screen time matches the records.
Where to point the cameras
  • Two cameras per pitch, each seeing about half. A small overlap in the middle is fine; a big one counts the same people twice.
  • Include the touchlines and goal areas; avoid looking straight into floodlights or the low sun.
  • Once a camera works, draw the pitch boundary for it on the Boundaries page, so people on the next pitch are not counted.
Checking the network
  • Check the address in VLC: Media > Open Network Stream, paste the address. If VLC shows video, this system can read it.
  • Firewalls: the Mini-PC must reach the camera on its RTSP port (usually 554).
  • Remote sites: connect them over a VPN. Never forward the RTSP port to the internet - anyone could watch the pitch and try the password.

Privacy
  • The cameras film identifiable people. Put up signs and follow your local rules for CCTV.
  • Camera addresses and passwords stay in configs/cameras.json on this computer only; this page never shows a saved password.
  • Pictures are not stored unless the live worker is started with --evidence-dir; this page's snapshots are not saved at all.
