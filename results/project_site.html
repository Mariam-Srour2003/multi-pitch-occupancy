Pitch Occupancy.

Master's thesis · CPU-only computer vision

Auditing how football pitches are actually used

One frame per camera per minute, classified as empty, active play or maintenance, aggregated into a USED / NOTUSED / REVIEW verdict, then reconciled against what the facility’s booking records claim. Entirely on one CPU, with no GPU anywhere in the system.

The finding that reframed the project. A rule that reads only the clock — “if night then playing, else empty” — scores 98.4% on the labelled data, matching every model the pilot benchmarked. Class and scene are the same variable in this dataset: empty pitches are 98% daytime, active play 99% night. Accuracy measured here cannot distinguish classifying occupancy from recognising a place.

Everything since has been about building an evaluation that can tell the difference.

What the argument became

  • The evaluation was uninformative — a colour histogram beat a deep probe under a random split.
  • The models were not the problem — across unseen venues the trivial baselines collapse while the frozen backbones hold.
  • The protocol reverses the decision — ViT ranks first under the leaky split and last under the honest one.
  • The models genuinely read people — blurring away the players costs 0.12 recall; removing colour or the background does not.

One gap explains four blocked questions. No empty pitch exists outside a single venue. That single fact makes cross-venue three-class evaluation, the calibration study, the risk–coverage operating point, and the clean version of the leakage comparison all unanswerable.

The fix is not more data in general — it is full-length recordings from any second venue. A complete slot contains the empty periods before kickoff and after the whistle for free.

Where the frames come from

  • 4 slot recordings — one facility, two slots, two cameras each. The morning slot is almost entirely empty, the evening one almost entirely a match. This is the source of the confound.
  • 66 highlight clips — 10–14 seconds each, roughly nine venues, day and night. Every clip contains players (YOLO-verified, minimum 3, median 8), so they add venue diversity and daytime play but no empty pitches.

Conditions not covered

Lighting (day/night) is the only condition axis. There is no weather field and no rain footage — every frame is dry, so no claim about precipitation robustness is supported. See the ideas backlog for why rain would be valuable, and the trap it carries.

Searches

Tuning what goes in, not just what learns

Two configuration searches, both scored on cross-venue transfer and both guarded by a false-play control — every cross-venue test set is entirely active play, so recall can be bought by simply saying “playing” more often.

A searched prompt beats every trained probe, with zero labels. “people playing football on a pitch” reaches 0.988 cross-venue recall, above DINOv2’s 0.930 — which needed about 1,500 labelled frames. For active-play detection, onboarding a new site currently costs no labels at all.

The caveat is not small. The prompt was selected against the same folds it is scored on, and 375 candidates is a great deal of selection freedom. This is a development result. The locked final venues were held out throughout, so the honest confirmation — evaluate this one prompt on them, once — remains available.

Blurring costs 0.12 recall, and at that scale no individual person is visible — so the prediction rests on people, not scenery. Colour and the frame border are net distractions, each helping when removed. But not together: grayscale plus cropping falls below the untouched baseline. Removing information has a floor.

System

From a frame to a billing decision

frame source  ->  preprocess  ->  classify  ->  fuse two cameras
                                                      |
                                              aggregate the slot
                                                      |
                                    verdict + 3 evidence images
                                                      |
                                    reconcile against the booking record

Rules the system holds to

  • Never invent an observation. A camera that drops for a minute leaves a gap; a total outage yields REVIEW, not NOTUSED. No footage is not evidence a pitch was unused.
  • REVIEW never becomes an anomaly. The system may not convert its own uncertainty into someone else’s error.
  • Anomalies are per field, never per person. Attributing discrepancies to individuals adds no scientific value and considerable ethical exposure.
  • No verdict without its evidence. A verdict and the samples behind it are written in one transaction.
  • The system never bills. Output is decision support; a human confirms every anomaly.

Efficiency

All three backbones fit the 60-second sampling cycle with large margins, so latency is not the binding constraint — the model choice falls to accuracy. Measured on a 4-thread development laptop; the target Mini-PC must be measured separately.

Reproduce

Running the project

The code is not on main. All 39 commits sit on a stacked chain of feature branches; the tip holds everything.

Setup

git checkout feat/prompt-search
uv sync
uv run pitch info
uv run pytest -q -m "not slow"

Everyday commands

uv run pitch manifest      # rebuild the manifest, print confound warnings
uv run pitch coverage      # class x lighting x venue matrix
uv run pitch cache         # embed every frame per backbone (~25 min)
uv run pitch serve         # dashboard API on :8000

Reproduce every result

uv run python experiments/reproduce_all.py --check   # what is stale
uv run python experiments/reproduce_all.py           # run what is missing

Stages verify their own outputs and report BLOCKED rather than skipping when an input is missing — a reproduction script that exits 0 having done nothing is worse than one that fails.

Individual experiments

uv run python experiments/h3_cross_venue_recall.py
uv run python experiments/prompt_search.py --limit 600
uv run python experiments/preprocess_search.py --check   # cost estimate first
uv run python experiments/make_figures.py

Do not pass --limit to the preprocessing search for a number you intend to quote. Subsampling shrinks the venue folds until recall can only take a few discrete values; the script warns when it happens.
